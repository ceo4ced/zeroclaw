ZeroClaw: Agent Orchestration Platform

A managed platform for deploying, coordinating, and scaling multi-agent AI systems. We sell agent orchestration — not commodity hosting.

Updated: February 2026  |  Supersedes: v1 (March 2026 draft)

1. Executive Summary

ZeroClaw is a managed agent orchestration platform built on SpacetimeDB. It enables developers and businesses to deploy multi-agent AI systems with real-time coordination, persistent memory, security policy enforcement, and tool execution — without managing infrastructure.

Unlike generic cloud hosting, ZeroClaw provides purpose-built agent infrastructure: multi-agent state synchronization, conversation memory, security policy enforcement, and a tool execution sandbox. This is the value layer that justifies premium pricing over raw compute.

What Changed from v1

The original plan positioned ZeroClaw as infrastructure hosting at commodity prices ($5/user/month) with a single revenue stream (subscriptions). This revision repositions around value-based pricing with four revenue streams, an enterprise tier, and usage-based components that align revenue with actual customer value.

2. Core Insight: Sell Orchestration, Not Hosting

The v1 plan sold infrastructure at cost-plus margins. The problem: anyone can rent a VPS for less. The value of ZeroClaw is not "a server that runs agents" — it is:

  • Multi-agent coordination — real-time state sync between agents via SpacetimeDB subscriptions, something that requires custom engineering to build from scratch.
  • Persistent, searchable memory — agents remember across sessions, with category-scoped recall and (planned) semantic search.
  • Security policy enforcement — rate limits, cost caps, tool allowlists, and content filtering applied per-agent, managed centrally.
  • Tool execution sandbox — shell, file, browser, and hardware tool execution with input validation and audit trails.
  • Zero-ops deployment — spacetime publish and you're live. No Docker, no Kubernetes, no queue infra.

This is agent middleware, not generic hosting. Pricing should reflect the engineering cost saved, not the compute consumed.

Positioning
Analogy: Stripe vs. a payment gateway. Stripe doesn't compete on "cheapest way to process a credit card." They sell developer experience, fraud prevention, and business tooling. ZeroClaw should sell developer experience, agent coordination, and operational safety — not the cheapest way to run an LLM wrapper.

4. Revenue Model: Four Streams

The v1 plan had one revenue stream (subscriptions). This revision introduces four complementary streams that reduce single-point-of-failure risk and align revenue with customer value.

Revenue Stream 1: Platform Subscriptions
  Predictable base revenue. Tiered by agents, memory, policies.
  Free → Builder ($29) → Team ($99) → Enterprise ($499–999)

Revenue Stream 2: Usage-Based Compute
  Scales with customer success. Charged per agent-hour and per GB stored.
  Included base → metered overage at transparent per-unit rates.

Revenue Stream 3: Managed LLM Proxy (Optional)
  Convenience billing. Users can optionally route LLM calls through ZeroClaw.
  Margin on pass-through + unified billing + rate limiting + cost controls.
  BYOK remains available for power users who prefer direct API access.

Revenue Stream 4: Marketplace & Add-Ons
  Ecosystem expansion. Premium tools, agent templates, integrations.
  Revenue share with third-party developers (70/30 split, creator-favorable).

Why Four Streams

  • Subscriptions provide predictable MRR for planning and fundraising.
  • Usage-based pricing ensures heavy users pay proportionally — and that revenue grows as customers succeed.
  • Managed LLM proxy captures value from the highest-spend item (LLM tokens) without forcing users onto it. BYOK stays as the power-user default.
  • Marketplace creates an ecosystem moat and recurring revenue from third-party contributions.

New: Usage Metering Infrastructure

The v2 architecture adds usage_meters and billing_events tables to SpacetimeDB. Every agent invocation, tool execution, and storage allocation is recorded atomically alongside the operation itself. This enables accurate usage-based billing without external metering services.

New: LLM Proxy Layer

For users who opt into the managed proxy, LLM calls route through a ZeroClaw proxy procedure that: (1) tracks token usage per agent, (2) enforces cost caps from the security policy, (3) provides unified billing. For BYOK users, calls go direct via ctx.http with the user's own key — same as v1.

Technical Corrections Carried Forward from v1

  • Isolation: Tables use agent_id + owner: Identity (via ctx.sender), not user_id. A tenant_id layer is needed for multi-tenant hosting.
  • Memory: Current implementation uses keyword-based recall (word matching >3 chars), not vector embeddings. Embedding support is a post-launch enhancement.
  • API keys: Stored in plaintext in POC. Encryption at rest is a launch-blocking requirement.
  • Procedures: Require SpacetimeDB "unstable" feature flag. Use explicit with_tx blocks (not full-procedure transactions).
  • Table visibility: All tables currently public. Must be changed to private before hosting any external users.

9. Go-to-Market Strategy

Phase 0: Security Hardening (Week −2 to 0)

Gate: No external users until complete.

  • Make agents table private (API key exposure fix).
  • Add tenant-level isolation above agent_id.
  • Implement API key encryption at rest.
  • Enforce rate_limit_per_minute in orchestration loop.
  • Add input validation/sanitization for tool parameters.
  • Deploy usage metering tables and billing event tracking.

Phase 1: Private Beta (Week 1–3)

  • Invite 20–30 users from ZeroClaw community and SpacetimeDB Discord.
  • All users on free tier; focus on finding product-market fit signals.
  • Track: activation rate (deploy first agent), retention (return in week 2), feature usage.
  • Conduct 5–10 user interviews to validate pricing willingness.

Phase 2: Public Launch with Paid Tiers (Week 4–6)

  • Launch on Product Hunt, Hacker News, Reddit (r/LocalLLaMA, r/selfhosted, r/SaaS).
  • Enable Builder and Team tiers with 14-day free trial (no credit card required).
  • Publish "Deploy Your First Multi-Agent System in 5 Minutes" tutorial.
  • Launch referral program: give $10 credit, get $10 credit.

Phase 3: Growth + Enterprise Pipeline (Month 2–6)

  • Content marketing: case studies, "how we built X with ZeroClaw agents" posts.
  • Enable managed LLM proxy for users who request unified billing.
  • Begin enterprise outreach: target AI-native startups and dev teams at mid-size companies.
  • Ship team features: shared agent workspaces, role-based access, audit logs.
  • Launch marketplace beta with 5–10 first-party tool templates.

Phase 4: Scale (Month 6–12)

  • Open marketplace to third-party developers.
  • Add SSO/SAML for enterprise tier.
  • Evaluate dedicated instance offering for enterprise customers with compliance requirements.
  • Explore partnerships with AI tool directories and developer platforms.
  • Begin evaluating seed funding if MRR trajectory supports it (target: $10K+ MRR).

Pricing too high for early adoptersMediumMedium 14-day free trial removes friction. Builder at $29 is below "needs approval" threshold for most developers. Adjust based on conversion data.

SpacetimeDB procedure instabilityMediumHigh The "unstable" feature flag means API may change between versions. Pin SpacetimeDB version. Implement retries with exponential backoff. Monitor error rates closely.
SpacetimeDB pricing changesMediumHigh Current margins are wide enough (90%+) to absorb 2–3x cost increases. Maintain relationship with SpacetimeDB team. Have contingency plan for self-hosted SpacetimeDB if cloud pricing becomes untenable.
Multi-tenant data leakageLowCritical Phase 0 security hardening is a launch gate. Private tables + ctx.sender enforcement + tenant isolation layer. Security audit before public launch.
LLM proxy liability (content / abuse)MediumMedium Clear ToS: users are responsible for content generated via their agents. Rate limiting and cost caps prevent runaway usage. Content filtering for obvious abuse patterns.
Open source competitionHighHigh ZeroClaw itself is open source — the managed platform competes on convenience, not code. Maintain feature velocity on the hosted platform (team features, marketplace, enterprise). The "open core" moat is the multi-tenant orchestration layer.

11. Open Core Strategy

ZeroClaw's dual license (MIT + Apache 2.0) enables an open core model:

LayerLicenseWhat's Included
Open Core MIT + Apache 2.0 Agent runtime, providers, channels, tools, memory backends, CLI, config system. Anyone can self-host for free.
Hosted Platform Proprietary (SaaS) Multi-tenant orchestration, usage metering, billing, team management, audit logs, managed LLM proxy, marketplace, enterprise features (SSO, SLA, dedicated instances).

This model is proven by GitLab, Sentry, PostHog, and others. The open source project drives awareness and trust; the hosted platform captures revenue from users who value convenience, collaboration, and support over self-hosting.

Strategic Note
Keep the open source project healthy. The hosted platform's value proposition depends on the core runtime being genuinely useful and well-maintained. Starving the open source project to force hosted adoption is a losing strategy — it destroys trust and community. Invest in both.

14. Conclusion

ZeroClaw's competitive advantage is agent orchestration — multi-agent coordination, persistent memory, security policies, and tool execution — not generic cloud hosting. The v2 business plan aligns pricing with this value through four revenue streams, usage-based scaling, and an enterprise tier that captures high-value customers.
